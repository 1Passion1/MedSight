# 02 - 需求分析

## 2.1 业务需求

| 编号 | 需求 | 优先级 |
| --- | --- | --- |
| BR-01 | 对胸部 X 光自动识别常见异常并给出置信度 | 高 |
| BR-02 | 对胸部 CT 检测肺结节并定位 | 高 |
| BR-03 | 提供分诊排序，优先展示疑似重症病例 | 中 |
| BR-04 | 生成结构化报告草稿供医生修改 | 中 |
| BR-05 | 所有结果可追溯、可接入 PACS/RIS | 高 |

## 2.2 功能需求

### 2.2.1 数据接入
- 支持 DICOM、PNG、JPEG、NIfTI 输入；
- 支持从 PACS 拉取或批量导入；
- 去标识化：移除患者姓名、ID、检查号等 PHI。

### 2.2.2 影像预处理
- 窗宽窗位调整、重采样到统一像素间距；
- 图像归一化、裁剪黑边、对齐；
- 数据增强（训练阶段）。

### 2.2.3 模型推理
- 分类：输出各病种概率；
- 检测：输出病灶边界框 + 类别；
- 分割：输出病灶掩膜；
- 支持批量与实时（单张）两种模式。

### 2.2.4 结果呈现
- 影像叠加热力图（Grad-CAM）突出可疑区域；
- 结构化输出（JSON）含病种、概率、定位、模型版本。

### 2.2.5 质控
- 低质量/不合格影像识别并告警；
- 模型不确定样本标记，转人工复核。

## 2.3 非功能需求

| 类别 | 要求 |
| --- | --- |
| 性能 | 单张 GPU 推理 ≤ 100 ms；批量吞吐 ≥ 50 张/秒 |
| 可用性 | 服务可用性 ≥ 99.9% |
| 可靠性 | 失败重试、降级到人工阅片 |
| 安全 | PHI 加密存储、传输 TLS、访问审计 |
| 可扩展 | 支持新增病种/模态而不重构 |
| 可解释 | 提供可视化依据，避免纯黑盒 |
| 合规 | 符合医疗器械软件（SaMD）相关法规 |

## 2.4 用户故事（示例）

- 作为**影像科医生**，我希望系统按风险对当日检查排序，以便我先看最可能异常的病人。
- 作为**基层医生**，我希望看到可疑区域的直观标注，以便判断是否需要转诊。
- 作为**质控人员**，我希望查看模型版本与置信度分布，以便发现模型漂移。

## 2.5 假设与约束

- 训练数据需经过伦理审批与去标识化；
- 黄金标准（Ground Truth）来自病理或多名资深医生共识；
- 初期不覆盖罕见病，避免长尾导致不可靠输出；
- 模型输出为**辅助建议**，最终由医生决策。
