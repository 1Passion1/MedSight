# 09 - 项目计划

## 9.1 里程碑与时间线（示例，可调整）

| 阶段 | 里程碑 | 主要交付物 | 预计周期 |
| --- | --- | --- | --- |
| M0 | 立项 | 需求文档、可行性分析 | 2 周 |
| M1 | 数据准备 | 伦理审批、去标识化、标注完成 | 6–10 周 |
| M2 | 基线模型 | 训练评估闭环、基线指标 | 4 周 |
| M3 | 模型优化 | 多病种、多中心、性能达标 | 8–12 周 |
| M4 | 系统集成 | 推理服务、PACS 对接、工作站 | 8 周 |
| M5 | 验证与合规 | 外部验证、临床试用、注册 | 6–12 月 |

> 医疗项目周期长，尤其数据与合规环节不可压缩。

## 9.2 团队角色

| 角色 | 职责 |
| --- | --- |
| 项目负责人 | 统筹、资源、进度 |
| 算法工程师 | 模型设计、训练、优化 |
| 数据工程师 | 数据管线、标注管理、质控 |
| 后端工程师 | 推理服务、系统集成 |
| 影像医生顾问 | 标注标准、临床需求、验证 |
| 合规/法规 | 伦理、注册、质量体系 |

## 9.3 工作分解（WBS，示例）

- **数据**
  - 伦理审批
  - 数据采集与去标识化
  - 标注与质控
  - 数据集划分与版本管理
- **算法**
  - 基线复现
  - 骨干与损失实验
  - 校准与可解释
  - 外部验证
- **工程**
  - 推理服务
  - PACS/RIS 集成
  - 部署与监控
- **合规**
  - 风险管理
  - 临床评价
  - 注册申报

## 9.4 风险登记册

| 风险 | 概率 | 影响 | 应对 |
| --- | --- | --- | --- |
| 数据获取困难 | 中 | 高 | 优先公开数据集起步，同步谈院内数据 |
| 标注质量不足 | 中 | 高 | 多医生共识 + 仲裁 + 抽检 |
| 外部泛化差 | 中 | 高 | 多中心训练、域泛化 |
| 合规周期长 | 高 | 高 | 尽早启动法规咨询 |
| 算力不足 | 中 | 中 | 云算力弹性、模型蒸馏 |
| 人员流动 | 中 | 中 | 文档化、代码规范 |

## 9.5 质量保证

- 代码：单元测试、代码审查、CI；
- 数据：标注一致性、抽检；
- 模型：固定随机种子、可复现实验；
- 文档：设计、变更、实验记录同步更新。

## 9.6 成功标准

- 主要病种在外部测试集达到预设 AUROC/灵敏度；
- 通过临床试用，医生接受度良好；
- 完成合规所需文档与验证；
- 形成可迭代的工程与数据闭环。

## 9.7 后续演进方向

- 多模态融合（影像 + 电子病历 + 检验）；
- 3D/视频（CT 序列、超声动态）；
- 联邦学习（数据不出院的多中心协作）；
- 基础模型/大模型在医学影像的应用；
- 主动学习降低标注成本。
