# 06 - 系统架构

## 6.1 总体架构

```
┌──────────────────────────────────────────────────────────────┐
│                          接入层                                │
│   PACS / RIS / 影像工作站 / Web 上传 / 移动端                  │
└──────────────────────────────────────────────────────────────┘
                             │  DICOM / HTTP / HL7 / FHIR
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                          网关层                                │
│   认证鉴权 · 限流 · 路由 · 审计日志                            │
└──────────────────────────────────────────────────────────────┘
        │                    │                     │
        ▼                    ▼                     ▼
┌───────────────┐  ┌──────────────────┐  ┌──────────────────┐
│ 影像服务       │  │ 推理服务          │  │ 报告服务          │
│ DICOM 解析     │  │ 预处理+模型推理   │  │ 结构化报告生成    │
│ 去标识化       │  │ 分类/检测/分割    │  │ 可视化/热力图     │
└───────────────┘  └──────────────────┘  └──────────────────┘
        │                    │                     │
        └────────────────────┴─────────────────────┘
                             │
                             ▼
┌──────────────────────────────────────────────────────────────┐
│                          数据层                                │
│  对象存储(影像) · 关系库(元数据) · 缓存(Redis) · 消息队列       │
└──────────────────────────────────────────────────────────────┘
```

## 6.2 组件说明

| 组件 | 职责 | 技术选型 |
| --- | --- | --- |
| 接入层 | 对接 PACS/RIS、上传 | DICOM C-STORE、REST |
| 网关 | 鉴权、限流、审计 | Nginx / Kong / APISIX |
| 影像服务 | DICOM 解析、去标识化、格式转换 | pydicom、SimpleITK |
| 推理服务 | 加载模型、批量/实时推理 | FastAPI + Torch/ONNX |
| 报告服务 | 生成结构化结果与可视化 | Python、matplotlib |
| 任务队列 | 异步批处理 | RabbitMQ / Kafka |
| 对象存储 | 存放影像 | MinIO / S3 |
| 关系库 | 检查、任务、结果元数据 | PostgreSQL |
| 缓存 | 热点结果、会话 | Redis |

## 6.3 推理服务设计

### 6.3.1 接口

```
POST /v1/predict
Content-Type: multipart/form-data
  file: <影像文件>

200 OK
{
  "study_id": "abc123",
  "model_version": "v0.2.0",
  "predictions": [
    {"label": "Pneumonia", "probability": 0.93},
    {"label": "Effusion", "probability": 0.41}
  ],
  "findings": [
    {"label": "Nodule", "bbox": [120, 80, 200, 160], "score": 0.88}
  ],
  "heatmap_url": "/artifacts/abc123_cam.png",
  "uncertainty": 0.07
}
```

### 6.3.2 处理流程

1. 接收影像 → 校验格式与完整性；
2. 预处理（与训练一致）；
3. 批处理/实时推理；
4. 概率校准 + 阈值判定；
5. 生成热力图与结构化结果；
6. 返回并落库。

### 6.3.3 性能设计

- **批处理**：后台队列消费大批量检查；
- **实时**：单张低延迟，GPU 常驻；
- **缓存**：相同影像哈希命中直接返回；
- **弹性**：按队列长度自动扩缩容。

## 6.4 与医院系统集成

| 系统 | 集成方式 |
| --- | --- |
| PACS | DICOM 查询/获取/回写 |
| RIS | HL7 / FHIR 对接检查信息 |
| 工作站 | 嵌入插件展示 AI 结果 |
| 报告系统 | 结构化结果回写草稿 |

## 6.5 高可用与容灾

- 推理服务多副本 + 负载均衡；
- 无状态服务，模型权重挂载共享存储；
- 数据库主从、定期备份；
- 降级策略：模型不可用时回退人工阅片。

## 6.6 安全设计

- 全链路 TLS；
- 基于角色的访问控制（RBAC）；
- 操作审计日志；
- PHI 加密存储与脱敏展示；
- 模型与数据访问隔离。

## 6.7 可观测性

- 指标：QPS、时延、GPU 利用率、错误率；
- 日志：结构化日志集中收集；
- 追踪：分布式链路追踪；
- 告警：时延/错误率/漂移阈值触发。
